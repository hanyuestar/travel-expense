# 部署指南

三种部署方式任选其一。数据始终落在你自己的磁盘（`routes.json`）。

---

## 方式 A：Docker 自托管到群晖 NAS（推荐，无需新域名）

你已有 `survey.hanyueppy.synology.me` 的 DDNS + 反代，照同样方式加个子域（如 `travel.hanyueppy.synology.me`）即可。

### 1. 传文件
把整个 `travel-expense/` 文件夹传到 NAS（如 `/volume1/docker/travel-expense/`），确保 `data/routes.json` 在。

### 2. 启动容器
```bash
cd /volume1/docker/travel-expense
docker compose up -d
```
- 端口 `3006 → 3000`（改端口编辑 `docker-compose.yml`）。
- 数据卷 `./data:/data` 已映射，改动落盘到 NAS。

验证：`curl http://localhost:3006/api/routes` 返回已有路线。

### 3. 反向代理
群晖 `控制面板 → 登录门户 → 高级 → 反向代理 → 新增`：
- 来源：`travel.hanyueppy.synology.me`，HTTPS，端口 `443`
- 目的地：本机 `localhost`，端口 `3006`，HTTP
- 勾选 HSTS 即获 `*.synology.me` 免费证书

打开 `https://travel.hanyueppy.synology.me` 即可（户外访问需路由器把 443 转发到 NAS）。

---

## 方式 B：使用预构建镜像（ghcr.io / Docker Hub）

不想本地构建，直接拉预构建镜像：

```bash
# GitHub Container Registry
docker run -d --name travel-expense -p 3006:3000 \
  -v /your/path/data:/data \
  ghcr.io/hanyuestar/travel-expense:latest

# 或 Docker Hub
docker run -d --name travel-expense -p 3006:3000 \
  -v /your/path/data:/data \
  kyson666/travel-expense:latest
```
首次运行前先建好本地的 `data/` 目录并放入 `routes.json`（可从仓库 `data/routes.json` 复制）。

---

## 方式 C：手动运行（无 Docker）

需要 Node 18+：
```bash
cd travel-expense
node server.js          # 默认端口 3000
# 自定义端口与数据目录：
# PORT=8080 DATA_DIR=/path/to/data node server.js
```
浏览器打开 `http://localhost:3000`。

---

## 镜像发布方式（维护者参考）

代码推送到 GitHub 后，镜像通过 **GitHub Actions 自动双注册表发布**（参考 `docker-image-publish` 流程）：

1. 仓库已配置 Actions Secret：`DOCKERHUB_USERNAME`、`DOCKERHUB_TOKEN`（ghcr 用自动注入的 `GITHUB_TOKEN`）。
2. 打版本 tag 并推送即触发构建：
   ```bash
   git tag -a v1.0.0 -m "v1.0.0"
   git push origin main --tags
   ```
3. Actions 会把镜像推到 `ghcr.io/hanyuestar/travel-expense` 与 `kyson666/travel-expense`，`latest` 始终指向最新。
4. 也可在仓库 Actions 页面手动 `workflow_dispatch` 触发。

> 修改代码后：`docker compose build && docker compose up -d`（本地构建场景），或等 CI 出新 tag 镜像后改 `docker-compose.yml` 的 `image:` 指向新版本。
