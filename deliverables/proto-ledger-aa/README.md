# 交互原型 · 逐笔消费流水 + AA 分账（含既有功能）

配套 PRD：[`../prd-ledger-aa-2026-09-18.md`](../prd-ledger-aa-2026-09-18.md)
（第 0.1 节为**实施记录**：本原型已按评审意见对齐最终产品 —— **取消「流水模式 / 无流水模式」开关**、路线表单**移除 9 类花费输入**、AI 规划**同时回填备注**）

> **用途**：一处点通「新功能 + 既有功能」，评审交互与冲突面。
> 纯前端演示，数据在内存中，**刷新即重置**，不连接任何后端。
> 本原型与已发布的 v1.1.0 行为一致，可作为功能说明的可交互版本。

## 打开方式

直接双击 `index.html` 即可（无需服务端、无需构建、无需安装依赖）。

## 覆盖范围

| 类别 | 内容 |
|---|---|
| **新功能** | 路线卡流水徽标与「＋ 记一笔」、详情三页签（概览 / 流水 / 结算）、记一笔、同行人管理、最少转账方案 |
| **既有功能** | 新增路线表单、编辑路线表单（**无 9 类花费输入，由流水自动汇总**）、AI 规划（**同时生成注意事项与美食推荐并写入备注**）、AI 调整多轮对话、删除路线 |

> AI 调用为**本地模拟**（原型无后端）。真实契约：`POST /api/routes/ai-plan`、`POST /api/routes/ai-chat`，
> 服务端打到 OpenAI 兼容的 `{api_base_url}/v1/chat/completions`。模拟只影响「模型输出内容」，不影响交互评审。

## 设计约束

严格复用 `public/styles.css` 的既有元素、组件与颜色，不引入新视觉语言：

| 项 | 做法 |
|---|---|
| 样式来源 | `styles.css` 是 `public/styles.css` 的**逐字节副本**，保证视觉同源 |
| 三页签 | 复用登录页同款 `.tabs/.tab/.tab.active` |
| 弹层 / 表单 / 表格 / 面板 | 复用 `.mask` `.sheet` `.field` `.exp-grid` `.table-wrap` `.tbl` `.panel` `.kv` `.chip` `.pill` `.toast` |
| 路线表单 | 按 `public/index.html` 的 `#formMask` **1:1 复刻**（字段、`id`、9 类输入格结构均一致） |
| AI 面板 | 按 `public/index.html` 的 `#aiChatMask` **1:1 复刻** |
| 颜色 | 全部走既有 CSS 变量（`--primary` `--danger` `--accent` …）；分类色沿用 `charts.js` 的 `COLORS`；同行人头像**复用已定义未使用的 `--c0`…`--c8`** |
| 新增样式 | 仅集中在 `proto.css`（含落地时的合并说明），不覆盖任何既有类 |
| 依赖 | 零新增（无图表库、无 UI 框架、无构建） |

## 可交互验证路径

1. 工作台 → 首张卡片「查看」→ 默认落在 **流水** 页签
2. 顶部 chips 筛选类目 → 点击任一行进入编辑
3. 切 **结算** 页签 → 核对每人差额与「最少转账方案 共 3 笔」
4. 底部 **＋ 记一笔** → 改金额 / 类目 / 付款人 / 分摊人（观察实时人均）→ 保存后回看流水与结算变化
5. 底部 **同行人** → 批量添加（逗号分隔）→ 观察「与人数不一致」提示
6. 观察**全站无任何模式切换入口**（原型条仅有「重置演示数据」）；两条示例路线都由流水承载金额（第二条由「期初（历史数据）」流水承载原有 9 类金额）
7. **既有功能**：工具条「＋ 新增路线」→ 填名称与起止日期（天数自动计算）→「AI 规划」→ 观察**备注被写入「注意事项 + 美食推荐」** →「调整」多轮对话 →「应用此版本」→ 保存
8. **表单口径**：编辑任一路线 → 观察**没有 9 类花费输入格**，只有「由逐笔流水自动汇总（当前 N 笔）」提示 + 「去记流水」直达
9. 原型条「AI 权限：未启用」→ 编辑页的 AI 按钮全部消失（与真实权限规则一致）

## 已知取舍与发现（详见 PRD 第 14 章与附录 B）

- **ledger 模式的唯一可见改动**：编辑路线时 9 类花费转只读 + 黄条提示；保存时**不提交**这 9 个数值，由服务端以流水聚合结果为准（否则会把聚合值清零 —— 已实测复现）。
- 原型允许「0 位分摊人」保存，语义为**纯记录本人实付、不作 AA 依据**（`split_mode='none'`），此时 `Σ实付 ≠ Σ应分担`，结算页会给出差额解释。
- 人均分母优先取**同行人名单**，名单为空回退 `routes.people`；两者不一致时仅提示、不自动改写。
- 预算进度条样式在 `public/styles.css` 中曾**缺失**（线上该条不可见）；**v1.1.0 已正式修复**（规则已合并进 `public/styles.css`），原型 `proto.css` 保留同样规则。
- 弹层内的主按钮（`.btn-primary`）实为绿色 header 设计，白底弹层里对比度偏弱；原型用行内样式临时替代，建议正式补一个填充态类。

## 维护提示

- 内置 HTML 预览器会在打开时向本地 HTML **注入 `data-page-node-id` 属性**（仅影响体积，不影响功能）。若要在提交前保持文件干净，先关闭预览再执行：

  ```bash
  python -c "import io,re; s=io.open('index.html',encoding='utf-8').read(); io.open('index.html','w',encoding='utf-8',newline='\n').write(re.sub(r'\s+data-page-node-id=\"[^\"]*\"','',s))"
  ```

- 修改 `index.html` 后请重跑两个验证脚本，确认断言仍全绿。
